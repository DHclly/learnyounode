创建两个文件，分别名为 `make-it-modular.js` 和 `mymodule.js`。

这道题和上一道题相同，但引入了**模块**的概念。你需要创建两个文件来解决它。

编写一个程序，打印出指定目录下的文件列表，并按文件扩展名过滤。第一个参数是目录名，第二个参数是扩展名过滤器。把文件列表（每行一个文件）打印到终端。你**必须**使用异步 I/O。

你必须编写一个*模块*文件（`mymodule.js`）来完成大部分工作。这个模块必须*导出*一个函数，它接收**三个**参数：目录名、文件扩展名字符串和你的回调函数，顺序就是如此。在把它传给模块之前，不要以任何方式修改这个文件扩展名字符串。

这个回调函数必须使用 Node 惯用的 node(err, data) 约定来调用。这个约定规定：除非出现错误，否则传给回调函数的第一个参数是 null，第二个参数就是你的数据。在这道练习中，数据就是你过滤后的文件列表，以数组形式给出。如果你收到错误，例如来自 `fs.readdir()` 调用的错误，那么回调函数必须以这个错误作为第一个也是唯一的参数来调用。

你**必须**不要从你的模块文件直接向终端打印，只能从你原来的程序打印。

如果错误冒泡到你原来的程序文件，只需检查它并向终端打印一条有意义的信息。

这四件事就是你的模块必须遵守的契约。

1. 导出一个函数，它接收的参数与上述完全一致。
2. 按上述要求，用错误或某些数据恰好调用回调函数一次。
3. 不要改动其他任何东西，例如全局变量或 stdout。
4. 处理所有可能发生的错误，并把它们传给回调函数。

拥有契约的好处是，只要别人也期待这个契约，你的模块就能被他们使用。所以你的模块可以被其他任何做 learnyounode 的人使用，也可以被校验器使用，而且直接就能工作。

## 提示

通过创建一个新文件（`mymodule.js`）来建立一个新的模块，这个文件里只放你的目录读取和过滤函数。要定义*单一函数导出*，你可以把你的函数赋值给 `module.exports` 对象，覆盖掉原有的内容：

```js
module.exports = function (args) { /* ... */ }
```

或者你可以使用具名函数，并指派这个名称。

要在你原来的程序文件（`make-it-modular.js`）中使用你的新模块，请用 `require()` 调用来加载它，就像你用 `require('fs')` 加载 `fs` 模块一样。唯一的区别是，本地模块必须以 './' 为前缀。所以，如果你的文件名为 mymodule.js，那么：

```js
const mymodule = require('./mymodule.js')
```

这里的 '.js' 是可选的，你经常会看到它被省略。

现在，你模块中的 `module.exports` 对象被赋值给了 `mymodule` 变量。由于你导出的是单一的函数，`mymodule` 就是一个你可以调用的函数！

另外请记住，在回调函数中检查错误并提前返回是惯用做法：

```js
function bar (callback) {
  foo(function (err, data) {
    if (err) { return callback(err) } // 提前返回

    // ... 没有错误，继续用 `data` 做有趣的事情

    // 一切顺利，用 `null` 作为错误参数调用 callback

    callback(null, data)
  })
}
```

运行下面的命令来检查你的程序是否正确：

```sh
$ {appname} verify make-it-modular.js
```
