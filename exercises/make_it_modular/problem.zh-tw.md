建立兩個檔案，分別命名為 `make-it-modular.js` 和 `mymodule.js`。

這道題和上一道題相同，但引入了**模組**的概念。你需要建立兩個檔案來解決它。

撰寫一個程式，印出指定資料夾中經過副檔名篩選的檔案清單。第一個參數是資料夾名稱，第二個參數是副檔名篩選條件。把檔案清單（一個檔案一行）印到終端機。你**必須**使用非同步 I/O。

你必須撰寫一個*模組*檔案（`mymodule.js`）來完成大部分工作。這個模組必須*匯出*一個函式，它接收**三個**參數：資料夾名稱、副檔名字串和你的回呼函式，順序就是如此。在把它傳給模組之前，不要以任何方式修改這個副檔名字串。

這個回呼函式必須依照 Node 慣用的 node(err, data) 約定來呼叫。這個約定規定：除非出現錯誤，否則傳給回呼函式的第一個參數是 null，第二個參數就是你的資料。在這道練習中，資料就是你篩選後的檔案清單，以陣列形式呈現。如果你收到錯誤，例如來自 `fs.readdir()` 呼叫的錯誤，那麼回呼函式必須以這個錯誤作為第一個也是唯一的參數來呼叫。

你**必須**不要從你的模組檔案直接印到終端機，只能從你原本的程式印出。

如果錯誤冒泡到你原本的程式檔案，只需檢查它並向終端機印出一則有意義的訊息。

這四件事就是你的模組必須遵守的契約。

1. 匯出一個函式，它接收的參數與上述完全一致。
2. 依照上述要求，用錯誤或某些資料恰好呼叫回呼函式一次。
3. 不要改動其他任何東西，例如全域變數或 stdout。
4. 處理所有可能發生的錯誤，並把它們傳給回呼函式。

擁有契約的好處是，只要別人也期待這個契約，你的模組就能被他們使用。所以你的模組可以被其他任何做 learnyounode 的人使用，也可以被驗證器使用，而且直接就能運作。

## 提示

建立一個新檔案（`mymodule.js`）來建立一個新模組，這個檔案裡只放你的資料夾讀取和篩選函式。要定義*單一函式匯出*，你可以把你的函式指派給 `module.exports` 物件，覆寫掉原有的內容：

```js
module.exports = function (args) { /* ... */ }
```

或者你可以使用具名函式，並指派這個名稱。

要在你原本的程式檔案（`make-it-modular.js`）中使用你的新模組，請用 `require()` 呼叫來載入它，就像你用 `require('fs')` 載入 `fs` 模組一樣。唯一的差別是，本地模組必須以 './' 為前綴。所以，如果你的檔案名稱是 mymodule.js，那麼：

```js
const mymodule = require('./mymodule.js')
```

這裡的 '.js' 是選用的，你經常會看到它被省略。

現在，你模組中的 `module.exports` 物件被指派給 `mymodule` 變數。由於你匯出的是單一函式，`mymodule` 就是一個你可以呼叫的函式！

另外請記住，在回呼函式中檢查錯誤並提前回傳是慣用做法：

```js
function bar (callback) {
  foo(function (err, data) {
    if (err) { return callback(err) } // 提前回傳

    // ... 沒有錯誤，繼續用 `data` 做有趣的事情

    // 一切順利，用 `null` 作為錯誤參數呼叫 callback

    callback(null, data)
  })
}
```

執行下面的命令來檢查你的程式是否正確：

```sh
$ {appname} verify make-it-modular.js
```
